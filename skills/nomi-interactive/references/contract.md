# Portable contract snapshot

Generated from Nomi's generation contract. Snapshot: 2026-11-17. UI design refinements and unsupported preview features are documented in design.md.

Use nomi-interactive-ir/draft-2 + portable.learning/draft-2 (or unchanged draft-1 for legacy examples). Required fields: schema,id,version (positive integer revision),profile,requires,budget,state,derived,actions,root,nodes.
Capabilities version 1: Panel/Row {children:[nodeIds]}, Text {text,role?:"heading"}, Button {label}, Slider {label,min,max,step,marks?:[{value,label}]}, SegmentedControl {label,options:[{value,label}]}, Math {source}, Plot {series,markers,xAxis,yAxis,seriesLabels}, TextInput {label,multiline?:true}, Metric {label,value,unit?}, Table {caption?,columns:[strings],rows:[[string|number]]}, Scene {width:100..1200,height:80..800,label,items:[graphic]}.
Draft-2 enhanced components version 2 (declare requires.components and node.version BOTH as 2): Button adds icon?:"previous"|"restart", variant?:"primary"|"secondary", disabled?:boolean/expression; icon buttons retain label for accessibility. TextInput adds resetTargets?:[stateIds], reset to defaults whenever input changes, cannot target its own binding. TextInput hideLabel?:boolean hides the visible label while retaining its accessible name. Table adds hint?:short string, showCount?:boolean, emptyText?:short string, columnAlign?:array of left/right matching columns, visibleRows?:1..20, window?:"start"|"end", highlightRow?:-1..1023 (absolute row index, -1=none). Table v2 cells can also be {tokens:[strings],emphasis?:[tokenIndices],groups?:[[adjacent token indices]],joiners?:["+"|"→"]} for coordinated token chips; groups share one highlight background, emphasis highlights individual results, joiners has tokens.length-1 entries; </w> displays as ▁ with original token in tooltip. Expansion is view-local; include ALL data rows. Use version 1 for unchanged components.
Choose the requested presentation BEFORE selecting an example: an architecture/flow/dependency diagram uses Diagram nodes and edges; a step-by-step lesson uses Stepper; a comparison/table request uses Table. A follow-up such as "just an architecture diagram" overrides the previous table/lesson composition. Do not add tables, playback or mandatory controls to a diagram-only request.
Diagram version 1 (explicit requires.components.Diagram:1): {label,children:[nodeIds],edges:[{from:childId,to:childId}]}. 1..16 unique direct children and at most 24 edges, no cycles/self/duplicate edges. Topology must be static; use Panel children as node contents with short headings and ordinary Text/Input/TokenFlow etc. The host lays out branches and merges top-to-bottom with real arrow connectors; no coordinates, ASCII/Unicode arrows in Text, fake connector headings, or raw SVG. Diagram-only output can have empty state/actions and no controls. For one-sentence BPE architecture: put TextInput inside Corpus, compute learning.bpe(corpus,32) directly, branch BPE Training to Vocabulary and Merge Rules, then merge both into Tokenizer. Put compact complete results INSIDE those two nodes, no external tables or stepper. Show the merge budget concisely; do not imply this teaching tokenizer is production BPE. Keep the five-node topology from the user's sketch. Use the architecture example for this intent, not the four-table example.
Scene graphics: rect {type:"rect",x,y,width,height,fill?,stroke?}, circle {type:"circle",x,y,radius,fill?,stroke?}, line {type:"line",x,y,x2,y2,stroke?}, text {type:"text",x,y,text,fill?}. Colors ONLY ink,muted,accent,blue,green,orange,surface,none. Bind coordinates to expressions for live visualizations. No raw SVG/HTML/CSS/JS.
State types: number {default,min,max,step}, enum {default,values}, vector {default,itemType:"number",length}, string {default,maxLength:1..4096}; all require scope:"user". Slider constraints must exactly match its number state, SegmentedControl options exactly cover its enum, TextInput binds string via bind:{value:stateId}. Button uses on:{activate:actionId}.
Actions: {kind:"reset",scope:"user",targets:[stateIds]} or {kind:"set",scope:"user",target:stateId,value:EXPRESSION}. Clamp next/previous actions with min/max to stay in state bounds.
Expressions: literal {kind:"literal",value:JSON}, state/derived/variable {kind:K,id:ID}, call {kind:"call",function:F,version:1,args:[expressions]}, object {kind:"object",fields:{key:expression}}, map {kind:"map",variable:ID,items:expression,body:expression}, match {kind:"match",value:expression,cases:{enumValue:expression}}, sampleFamily (see wave example). No expression strings. All functions/expressions/components used must be declared in requires, hostEffects:[]; budget {maxSamplePointsPerSeries:128,maxSeries:8,maxStepsPerEvaluation:100000} (raise sample budget up to 512 if necessary).
Functions: math.softmax(vector,temperature), array.at(list,index), array.replaceAt(list,index,value); math.add/subtract/multiply/divide/pow/min/max(a,b), math.sin/cos(radians); number.format(value,decimals:0..8) returns string; string.concat(a,b); object.get(object,fieldName); array.length(list); learning.bpe(corpus,mergeCount).
learning.bpe computes REAL character BPE on whitespace-separated words (up to 1024 characters,128 words,32 merges; repeated words add frequency; reserved </w> marker forbidden in input). Output object fields: step,initialTokens,tokenCount (numbers), complete/atStart (booleans), nextPairIndex/newTokenIndex (-1 when absent, otherwise absolute row index for candidate/learnedVocabulary highlight), nextLabel (short next merge or completed label), tokenLabel (compact token summary), vocabularyWindow (start before the first merge, end afterward), candidateEmpty (short empty-state label), candidateRows [tokenCell,count,nextArrow], ruleRows [round,tokenCell,count], vocabularyRows [id,tokenCell,currentCount] with only the latest result token emphasized, segmentationRows [word,occurrenceCount,{tokens,emphasis,groups}] grouped by word with next non-overlapping merge positions highlighted, words rows [word,"token · token"], pairs rows [left,right,count] sorted by frequency, merges rows [step,left,right,joined,count], vocabulary rows [token,count] for CURRENT segmentation only, learnedVocabulary rows [stableTeachingId,token,currentCount] preserving the initial alphabet plus all learned tokens (zero current count is valid). Use learnedVocabulary for a final learned vocabulary, never label vocabulary as a complete tokenizer vocabulary. Use object.get to access these. Requested step can exceed completion: show computed step. Change corpus recomputes all steps. This is a teaching tokenizer, not production model tokenization.
For compact four-table BPE requests (use guided capabilities below for linear teaching): use enhanced version-2 controls/tables, resetTargets:["step"] on the corpus input, nextLabel and complete on the primary button, atStart to disable previous; 6 visible table rows (start for candidates, end for rules/vocabulary), first candidate highlighted and semantic token cells from segmentationRows. Keep one compact summary instead of multiple metric cards. Include an editable prefilled sentence, one-merge button, restart preserving the sentence, current segmentation beside the candidate pair-frequency table (first row is the next merge), ordered merge rules and vocabularyRows. Do not highlight entire rule/vocabulary rows: emphasize only the newly learned result token; render each candidate as token + token, and each rule as token + token → result. Use Row with child Panels for the two side-by-side tables; narrow screens stack. Show computed step, and clamp next to min(32, computed step + 1), not unbounded requested steps. For this four-table intent only, do not omit the candidate table. Architecture-only requests use Diagram and direct computed results instead.
For oscillating curves use 512 sample points and matching sample budget, and show only a few periods at the maximum frequency. Do not smooth or interpolate invented values.
Design: avoid implementation-limit paragraphs in the UI; use short labels and at most one brief explanatory sentence. One clear learning goal, concise heading, useful controls, visual result, optional short explanation. Use responsive Row with child Panels for genuinely parallel content, avoid a wall of tables or explanatory paragraphs. Prefer Scene/Plot for spatial/numeric relationships; Metric for key results. Each control must change a relevant visible result. Do not return temperature for unrelated requests. If impossible, return exactly {"error":"unsupported_interaction"}; never fake calculations with prerecorded outputs.
Guided learning capabilities (explicit requires): Panel version 2 adds visible:boolean/expression with static children; all Panel nodes must declare version 2 if used. TokenFlow version 1 props {label, hint?, layout:"words"|"chips"|"list", rows:[{id,tokens:[{id,text,tone:"normal"|"known"|"accent"|"muted",members:[strings],number?:integer}]}]}; stable IDs/members drive interruptible host motion. Stepper version 1 props {position,previousAction,nextAction,atStart,disabled,checkpoint,delay:200..5000,nextLabel}; action names must be static declared actions, other values may be expressions. Auto/manual playback is view-local, pauses at checkpoints and when offscreen; navigation never waits for animation.
learning.bpeWalkthrough(corpus,position) version 1 accepts up to 600 characters,128 words and position 0..228 (32 merges maximum). Returns position,next,previous,phase,round,atStart,disabled,complete,checkpoint,delay,nextLabel,title,progress,words,vocabulary,vocabularyLabel,vocabularyLayout,vocabularyHint,showWords,showPairs,showVocabulary,showMerge,showFinalRules,equation,pairs,rules. Bind TokenFlow rows to words/vocabulary/equation, pairs table columns [相邻词元,"",频次], rules [规则,顺序], Panel visible to show* fields. Phases split→pairs→merge→record→pairs repeat, then special→complete (numbering and ordered rules animate within this final step; no extra confirmation step). Restart resets position only; input resetTargets:[position]. Keep input visible at all phases. Final vocabulary starts with four example special tokens, then first-seen alphabet and learned merges; IDs are educational. Older targets must not be given undeclared capabilities. Use these guided capabilities for linear BPE teaching, not four simultaneous tables.
