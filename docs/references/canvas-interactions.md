# 画布选框、吸附与连接参考

查阅日期：2026-10-20。只记录事实摘要和设计取舍，不迁入第三方编辑器源码或私有格式。

- [tldraw Snapping](https://tldraw.dev/sdk-features/snapping)：bounds snapping 对齐边缘 / 中心 / 间距，handle snapping 用于端点；阈值按屏幕像素与 zoom 换算，参考线是瞬态反馈。
- [tldraw Handles](https://tldraw.dev/sdk-features/handles)：把不同交互用途的 handles 与对应几何行为分开。
- [Excalidraw 元素与绑定](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/api/excalidraw-element-skeleton)：箭头起终端可绑定到元素，绑定不是一组孤立的绝对坐标。

Nomi 的选择：选中时以蓝色矩形选框和四个方形角点表达缩放，控制层浮在内容上方，四边保留透明热区与方向 cursor；四侧外偏的浅蓝圆点直接拖出箭头，拖线期间其他对象显示目标圆点。连接点与边缘缩放热区分开，视觉尺寸和间距不随 zoom 改变。吸附默认开启、阈值 6 屏幕像素、Alt 临时关闭；Shift 锁轴。绑定写入平台中立 Connector，以 Placement / side 表示端点，标签、枚举线型与箭头可供 AI 或未来原生 renderer 解释。

当前是 Nomi 自有实现，未引入 tldraw / Excalidraw SDK，不宣称具备这些产品的全部能力。折线路由已读取两端 bounds，尚未避开第三方对象；等距分布、多选分组和缩放吸附已实现并有独立验证。

## 飞书白板在线对照：2026-10-20

用户授权通过 Open Browser Use 操作其空白示例画板，并检查该页面实际加载的 [白板 JS 1.0.0.7005](https://lf-package-cn.feishucdn.com/obj/feishu-static/lark/whiteboard/block/pc/x/1.0.0.7005/index.js)。以下为这一版本的观察，不代表飞书全部版本或完整路由能力。不将第三方实现复制进 Nomi；下载的调研材料只留在 ignored `.artifacts/feishu-routing/`。

### 已从 JS 确认的计算过程

1. **绑定数据与显示分开。** 两端保存对象 ID、归一化位置和吸附方向；端口随形状尺寸变化。自动路线与已手动编辑的折点走不同更新逻辑。
2. **读取两端形状 bounds。** 自动折线计算不仅依赖端口坐标。先得到端口的外侧邻点，通常位于形状 bounds 外 36 世界单位，再结合另一端相对形状边界的位置判断是否需要绕行。36 是绕行偏移，不能解读成所有终段均至少 36。
3. **按位置生成正交路径。** 双方无需绕行时走直线、L 形或中分折线；单方 / 双方绕行时按两端 bounds 的分离、重叠关系选折点。分离空间中的通道可以取两形状边界之间的中点，外绕通道取边界外 36。所检查的这段自动路由读取两端节点，不能把它描述成遍历所有对象的通用避障器。
4. **后处理与绘制独立。** 圆角折线通过 Canvas `arcTo` 绘制，默认半径 8，并受相邻可用线段长度的一半约束。箭头根据端段方向计算，结合线宽、标记尺寸和 padding 缩短绘制线身；近零端段有单独容错。
5. **文字与控制柄独立计算。** 标签沿路径累计长度定位，不按折点数组索引取中间。端段长度至少 48、中间段至少 16 才启用对应拖柄；控制柄绘制尺寸按 zoom 反算。手动折点有近零段清理和端段方向维护，线段吸附阈值为 `5 / zoom`。

代码定位线索仅供复核：bundle 模块 `81584` 分派自动 / 手动路线，`44084` 处理自动折点与手动折点调整；连接图元 drawer 处理圆角、箭头和标签。标识只对上述构建有效。

### 实际操作与限制

- 初始右侧 → 顶部连接，路径先进入两形状间的水平空隙，再走目标上方 36 单位，最后向下接入。
- 将源矩形从 120×80 缩至 60×30，目标上方通道仍距其顶部 36 单位，竖直通道随源右边界移动，符合两形状间隙中线的计算。
- 把目标移至源的左下方，路线仍先从源右侧出发，再经过两形状之间的纵向空隙进入目标顶部。读取的节点坐标与折点和画面一致。
- 把目标下移至其顶部比源右侧锚点低约 2 单位，飞书同样选择了极短终段的 L 形：视觉退化成横线末端挂向下箭头。其自动分支也没有统一保证可见终段长度，因此不能照搬后宣称解决 Nomi 的全部临界情况。
- 调整后均通过 Undo 恢复，并逐项检查形状位置、尺寸与连接折点；保留前后截图和结构摘录用于对照。

### 对 Nomi 的实现与保留边界

Nomi 已扩展为读取两端形状 bounds，用独立正交通道搜索选择形状间隙与外绕通道；近邻缩短通道、近齐平目标保持可见方向，保留手动折点与派生路径的分层。标签按累计长度定位、短段控制柄门槛和线段 5/zoom 吸附也已实现。实现与逐项对照见 [选择与布局矩阵](../design-docs/canvas-selection-and-layout.md)。

本轮还逐项打开并检查形状库、填充 / 边框、文字排版、更多操作、多选对齐 / 分布和组合菜单；原始观察材料留在 ignored 调研目录。参考菜单有云评论 / 协作等独立能力，未被当作本机画布的占位操作。实际拖动辅助线由 Nomi 自身 Electron 手势回归截图验证；没有把退出全屏后的无效拖动截图当作参考辅助线证据。

## 飞书连线端部留白：2026-10-25

通过 OBU 只读复核当前示例画板仍加载 1.0.0.7005，绑定线 lineProps.padding 为左右各 3；未修改画板。JS 的 xU 辅助函数通常为绑定对象返回 3（圆形端标与部分复合形状有特殊值），解绑端取 0。连线 drawer 将 padding 与端标长度补偿合并，沿端段方向后退箭头绘制点；逻辑绑定坐标保持在原边缘。该过程与端点外绕、折点、选中端点分别处理。

Nomi 使用自有绘制几何：3 屏幕像素净空加边框 / 线帽补偿，按弧长裁切内部生成的 L / Q / C 路径；标记前沿对齐绘制端点。保持原逻辑路线、边缘绑定和 DSL，不复制第三方实现或其私有模型。参考会话已结束，保留原用户示例页。
