# 个人云同步运行说明

2026-11-15：个人文稿同步 v1 已实现并完成本机隔离验证；后端已部署 amoylab，桌面同步尚未随新 DMG 发布。设计与默认调度见 [cloud-sync.md](cloud-sync.md)，验收进度见 [执行计划](../exec-plans/completed/20261115-personal-cloud-sync.md)。

## 当前入口与边界

桌面 Settings → 云同步。默认关闭，不登录不产生同步请求；服务不可用或同步状态损坏不阻止本地编辑。账号独立于 ChatGPT，以私有服务的运维账号登录。远程必须 HTTPS，loopback 开发可 HTTP。

首次明确选择上传到新云库，或下载已有云库；下载前备份当前本地资料库。不会按文稿标题猜测合并。同步身份包含服务、账号、云库和实际资料目录；切换目录会暂停旧绑定。退出只停用并删除本机登录凭据，保留本地文稿、outbox 和基线；联网时撤销当前设备会话，离线退出可在其他已登录设备撤销旧会话。

host 使用 Electron safeStorage 加密凭据，安全存储不可用时不保存明文替代品。renderer 只拿账号摘要、操作结果和显式请求的冲突内容，不拿 token。同步 sidecar 位于独立 userData/cloud-sync；正式版、开发版与隔离测试 profile 各自独立，不写入可携带的 `.nomi` 包。

## 本地事务与恢复

core 定义实体投影、三方比较与可控时钟调度；host 持久化冻结的 request ID / payload，写入和目录 fsync 完成才发请求。确认只更新该批次的实体基线，不推进拉取游标，不清掉新一代输入。请求成功但响应丢失后重试原请求；409 明确未提交才可换新请求。

接收端先合并已知基线、本机持久内容与远端变化，再通过当前编辑会话检查 revision、正文内容、输入法组合和待保存状态。任何新输入都拒绝这次远端应用，稍后重新计算；不会直接覆写编辑器文件。远端应用后清除早于该事务的整文稿 Undo 快照，避免旧快照还原时静默覆盖云端改动；之后的新编辑仍可撤销。

同实体冲突以本地 sidecar 保存双方与基线，设置页可查看并选择。选择前重新检查云端版本与本地内容；有后续编辑时要求重新查看。时间戳显示精度不构成竞争修改。选择前另保留该冲突副本。每次本地持久保存形成原子修改组，交叠保存保守合组；某组有冲突时保留整组，独立修改组继续同步。结构冲突暂停相关资料库提交。异常退出丢失保存分组边界时，以持久内容 / 基线对账保守合组，不猜测拆分。冲突查看带内容版本摘要，自动拉取刷新后旧选择会被拒绝。已处理冲突副本按最近 50 份或 30 天取并集保留；未处理冲突与 outbox 不清理。

保存事件、外部文件载入和前台扫描都进入对账；事件仅用于唤醒，持久文件才是上传来源。安静期 / 最大等待、节流和重试以设计数值为准；最早待上传时间、上次开始和退避时限写入设置，重启不会绕过退避。手动同步无本地变更时也立即拉取。

## 历史与恢复

设置页的「历史版本」按块列出旧版，支持分页预览、恢复及把已删除块放回指定文稿。当前版单独保存；归档版本保留最近 50 条与最近 30 天的并集。恢复是新的本地事务和云端版本，先备份本地库，不修改旧历史；当前块未同步、冲突、云端版本变化时拒绝覆盖。缺失的附件元数据从历史恢复，原件按不可变引用下载；缺失原件则整体失败。

服务启动和每 24 小时清理历史 / 90 天前连续日志前缀。`maintain` 默认只报告，`--apply` 执行；游标落在清理水位之前的设备通过旧基线 + 最新快照三方对账，不盲目覆盖。删除身份、提交收据与附件身份不随日志过期。对象审计保守保护所有已发布身份，只报告超过 7 天未发布原件，物理 GC 关闭。

## 运维边界

独立 Compose、显式 migration、配对备份 / 恢复与新库完整校验见 [部署说明](../DEPLOYMENT.md)。HTTP 日志仅记录操作类别、方法、状态码、耗时；不含正文、文件名、账号、token 或对象路径。设置页显示待同步 / 同步中 / 错误 / 冲突数及上次成功时间，维护报告包含清理候选和未发布原件容量。无公开 metrics 服务或生产告警平台。

v1 限制：每库 live payload 4 MiB / 4,000 个实体身份（含 tombstone），单附件 20 MiB；旧收据与删除身份持续保留，原件无自动回收，需监控数据库 / disk 容量。账号由运维创建，无公开注册、找回密码、共享或手机 UI。资料库历史恢复 UI 当前按内容块，不提供整库任意时间点回滚；灾备恢复使用配对备份。

## 验证

- `./scripts/test-sync-server.sh`：隔离 PostgreSQL 18、Go race、身份 / 版本 / 对象异常。
- `node scripts/check-sync-package.mjs`：真实 Go API、独立原生资料目录、原件摘要与单块增量。
- `node scripts/check-sync-package.mjs --desktop`：真实服务 + 两个 Electron 进程；独立 userData、资料目录、设备 ID 和登录凭据。覆盖默认关闭、实际登录表单、不同块离线汇合、同块冲突 UI 选择、外部 Markdown 修改、远端 Undo 保护、历史选择恢复、丢失提交响应与在途新输入、重启重放、设备撤销 / 重登录和停用后本地编辑；产物写入忽略的 `.artifacts/sync-package`。
- `node scripts/check-sync-package.mjs --backup`：真实数据库 dump、不可变原件归档、全新数据库 / 空对象目录恢复、9 张表比对及摘要验证；拒绝非空目标和损坏备份。
- `pnpm exec vitest run packages/core/src/sync packages/host/src/sync-engine.test.ts`：调度时钟、三方合并、冻结 outbox、丢确认 / 在途输入、编辑器竞争、旧游标重建和过期冲突选择。

所有 fixture 为 synthetic 文稿，本机双进程不代表双物理 Mac。未访问正式版资料。公网部署测试使用独立 synthetic 账号，不上传真实文稿；后端入口与运维见 [部署说明](../DEPLOYMENT.md)。

增量日志与历史分页同时受数量和字节预算约束，提交批次不拆分；首次全量为有预算上限的固定水位单响应。
