# 个人文稿云同步 v1

状态：2026-11-15，个人同步 v1 已实现，真实 Go / PostgreSQL、两个隔离 Electron 客户端、保留清理及备份恢复验证通过；未远端部署或发布。实现边界见 [运行说明](cloud-sync-runtime.md)。开发顺序见 [执行计划](../exec-plans/completed/20261115-personal-cloud-sync.md)。本文取代 [早期画布设计](notes-infinite-canvas.md) 中面向第一版同步的 CRDT / Node 协作房间建议，不改变当前本地保存行为。

## 目标与范围

提供可选开启的个人多设备同步。未登录、未开启、账号过期或服务不可用时，现有 `.nomi` 文稿仍可本地编辑、保存、导出。云同步不进入本地保存的成功条件，不要求桌面运行 Go 子进程。

v1 包含文稿、层级、稳定 block 身份、Markdown、交互 DSL、画布和附件；按 block 增量传输、按版本检查竞争修改。同一 block 并发修改保留双方并由用户选择，不实现字符级合并、CRDT、实时多人编辑、在线光标、家庭共享或手机编辑 UI。协议保留平台与 schema 版本，供未来 iPhone 使用。

## 存储分工

| 数据 | 云端位置 | 规则 |
| --- | --- | --- |
| 个人资料库、文稿身份、标题、父子关系和顺序 | PostgreSQL | 显式空间归属、版本与结构约束 |
| Markdown / LaTeX / 代码正文 | PostgreSQL `text` | 保留原文，不转换为渲染 HTML |
| 交互 DSL、画布 scene、块元数据 | PostgreSQL `jsonb` | 保留受支持的语义和未知附加字段；不承诺保留 JSON 排版 |
| block 当前版本、历史、删除记录、幂等记录与同步变更 | PostgreSQL | 与内容变更同事务提交 |
| 图片、PDF、音视频和其他二进制原件 | ObjectStore | 正文只保存稳定 asset ID 引用；禁止 Base64 内嵌 |
| 附件摘要、字节数、MIME、对象 key、上传状态 | PostgreSQL | 对象 key 不等于公开 URL，按空间鉴权 |

当前内容按 block 分记录，不把整库 / 整篇文稿存为一行可覆盖 JSON。v1 的内嵌画布 scene 仍是一个块，Markdown 块也可能包含多个段落；不宣称做到每段、每图形或每字符增量。共享块以空间内唯一内容实体同步，文稿 membership / 引用分开保存，不能为引用副本制造第二份权威内容。全局画布布局另作版本化记录。

本地 `.nomi` 仍是文件包；云端按语义存储，不镜像机器路径。改名 / 同库移动保留 ID；独立导入继续重新分配 ID。下载依据固定同步水位的清单取回内容及附件，在本机还原 `.nomi`；服务端打包 / ZIP 缓存是后续优化，不是首版前置条件。

### 开发阶段的 ObjectStore

先用服务器本地持久磁盘实现对象存储，Go 提供受鉴权的上传 / 下载 API；不开放静态目录，不要求 MinIO、云账号或客户端理解磁盘路径。复用现有 `StorageProvider` 的概念，个人同步有独立命名空间及生命周期，不沿用家庭资料的即时删除逻辑。

- 对象以空间隔离的 key 寻址，SHA-256 用于完整性检查及空间内去重；hash 不构成读取权限。
- 写入临时文件，校验大小与摘要，持久化后原子发布；已有原件不可覆盖，替换附件创建新身份。防止路径穿越、symlink 逃逸和未授权对象访问。
- `pending → ready` 的附件只有在原件完整持久化后才能被新的云端正文引用。附件准备期间本地文稿正常保存，相关同步批次等待；无依赖的其他文稿可以继续同步。
- 小文件首版可完整重传；上传请求幂等，断开后清理临时文件。分片续传后续按需要增加，不声称首版已有。
- Docker 使用持久卷，不能存镜像层或容器临时目录。数据库与对象目录都需要备份和恢复验证；单机 disk 不具备托管 OSS 的多副本耐久性。
- API 与领域层不依赖 FS 路径；以后切 S3 / OSS 只替换 provider / 传输能力。资产引用保持不变；迁移按清单复制、核验后切换，旧原件保留回退窗口。

## 本地保存与上传调度

以下为 v1 **初始默认值**，集中定义、可在测试中注入时钟与配置；不是已经上线的行为。暂不在用户设置里暴露多个调参开关。

本地保存沿用现有调度（当前文本保存防抖 700ms、最长等待 3s），云端另设调度。只有本地已持久保存且内容实际变化的版本才能入待同步队列；点击、光标、hover、重复保存、服务端回放不产生上传。

| 策略 | 默认值 / 行为 |
| --- | --- |
| 安静期防抖 | 同一文稿最后一次内容改动或产生新版本的保存完成后，连续 **3s** 无后续活动，提交最新已保存版本 |
| 持续编辑上限 | 自最早一条未上传且已持久保存的变化起，最多 **30s** 发起一次尝试；后续保存不重置这个起点 |
| 自动请求节流 | 同一文稿两次自动提交开始时间至少间隔 **5s**；同一文稿只允许一个提交在途 |
| 定时补偿 | 开启同步且 App 在运行时，每 **60s** 检查队列，找回到期但漏调度的上传；无变化不产生内容写入 |
| 远端拉取 | 前台每 **15s**、后台运行时每 **60s** 增量拉取；无变化返回空结果，不做全库内容下载 |
| 启动、恢复网络、唤醒、重新聚焦 | 合并事件后立即拉取并检查积压；已到期上传立即尝试，未到期保留原截止时间；重复事件不绕过节流或错误退避 |
| 手动同步 | 先完成本地保存，再触发上传和拉取；可绕过防抖 / 自动节流，不绕过鉴权、版本检查、服务端限流或在途互斥 |
| 关闭 / 退出 | 必须保留本地保存与持久队列；可尽力发起同步，但不为等待云端成功阻塞退出 |
| 网络 / 5xx 错误 | 2、5、10、30、60s 退避，后续上限 60s，增加 ±20% 抖动；成功后复位；离线期间不空转重试 |
| 429 / 401 / 冲突 | 429 遵守 Retry-After；401 暂停等待重新认证；冲突暂停相关批次，其他文稿可继续；校验错误不无限重试 |

正常自动上传截止时间为 `max(min(最后活动 + 3s, 最早待上传保存 + 30s), 上次自动提交开始 + 5s)`，再受网络、附件、退避、权限与在途请求约束。30s 是健康在线条件下的调度目标，不是断网或大附件时的完成承诺。持续输入到上限时上传当下已持久保存的稳定版本，不读取未保存草稿。

同块尚未发送的连续保存可合并为最新内容；跨块原子操作仍保持同一批次。在途批次冻结 payload 与 request ID，重试必须用同一内容；后续编辑保留为下一代，确认到达只能清除被确认的代，不能清掉新输入。连续变化回到已同步内容可消除未发送的空操作，已发送的修改要正常追踪确认。

调度状态按账号 / 远端空间 / 本地库绑定隔离；凭据保存在 host 安全存储，队列与同步基线不进入便携包。实现应以持久 outbox 和保存恢复对账保证崩溃安全：已保存但尚未排队的变化可重建，只有内存的回调不够。休眠恢复按截止时间重算，不追补数百次定时器。

## 提交、拉取与冲突

每个 block 以及可独立修改的结构记录都有云端 `version`；本地 `revision`、本地编辑代与云端版本分别维护。提交包含唯一 request ID、设备 ID、目标实体、baseVersion 与新内容 / 删除意图。新增也需要不存在预条件，不能用 upsert 复活已删除身份。

Go 在同一数据库事务内完成鉴权、幂等检查、基线校验、内容 / 历史写入、版本更新及变更日志追加。一个批次涉及的实体全部通过才提交。不同 block 修改可成功汇合；同 block 旧基线返回冲突而不是最后写入覆盖。采用本地版本也必须基于用户看到的最新云端版本重新提交，再次竞争继续报冲突。

文稿 block 顺序作为单独的版本化结构记录；同时重排按结构冲突处理。跨父节点移动校验相关版本与无环性；不能因不同记录同时提交造成循环。删除保留 tombstone，删除与编辑并发保留双方，禁止默默复活。冲突副本有明确恢复 / 选择入口；未解决的本地内容和所需附件不可被清理。

变更日志按空间提供不漏提交的游标。不能简单把可能乱序提交的数据库自增 ID 当作安全水位：v1 可在事务内串行更新该空间的同步计数器，确保日志提交顺序。客户端先持久应用一批远端变化及游标，再确认；失败重放幂等。远端更新走文稿领域事务，不直接覆盖 `.nomi`，不覆盖未保存输入，也不回声上传。Undo 不得让已接收远端修改被旧快照静默覆盖。

首次全量清单具有固定水位，分页期间变化从该水位后的日志补齐。资料库绑定明确区分上传本地库和下载已有云库，不按标题猜测合并；账号切换不复用前一个账号的基线。未知必需 schema / 内容类型保留原始数据并禁止破坏性写回，不把不支持的块当删除。

## 有界历史：最近条数与天数取并集

v1 默认每个版本化实体保留 **最近 50 条历史版本，或最近 30 天内的全部历史版本**，取并集。当前版本始终保留，不占历史 50 条额度。历史版本指成功云端提交后被替换的内容，不是每个按键或每次本地保存；同内容的幂等重试 / 空操作不新增历史。

```text
保留 = 当前版本
     ∪ 最近 50 条历史版本
     ∪ 最近 30 天内被归档的历史版本
     ∪ 正在使用 / 冲突处理中需固定保留的版本

可清理 = 排名超过 50 且归档时间早于 30 天前 且无保护引用
```

时间使用服务端 UTC 归档时间（旧内容被新版本替代的时间），条数按实体版本顺序计算，避免设备时钟和长期未改内容影响保留。例：半年没改也保留最近 50 条；一天改了 200 次则保留这 200 条；一共只有 8 条则全部保留。50 条不是总量硬上限，30 天内高频修改仍需容量监控，不能为了配额静默违背保留规则。

记录结构变化的实体同样遵循此规则。采用按块历史，恢复旧块作为一次新版本提交；**不承诺可恢复任意时刻的整篇文稿**。v1 不保存每次修改的整篇 / 整库快照。删除后的实体仍保留当前 tombstone 及按此规则保留的历史；“永久删除资料库 / 彻底清除历史”属于另一个显式流程。

用户历史、同步日志、幂等收据和 tombstone 是不同用途：

- 每天执行一次历史清理；当前内容与未解决冲突不因年龄被删除。
- 同步增量日志初始保留 90 天；旧游标返回 `reset_required`，客户端先保护 outbox / 冲突，再获取固定水位全量基线并对账，禁止把旧快照直接上传覆盖。
- 紧凑 tombstone 与 request ID / payload 摘要 / 提交结果收据在资料库生命周期内保留；不跟历史一起过期。完整响应可重建，后续压缩需先证明离线重放不会重复创建或复活内容。
- 不为永久离线设备无限保留日志；旧基线无法验证时保留待处理本地版本，不能推测为无冲突。

### 附件与历史一起保留

当前块、保留历史、回收内容、未解决冲突、有效上传会话及进行中导出所引用的原件都属于存活对象。相同原件不因版本历史重复拷贝，只保留引用。

只有彻底无引用且持续超过 **7 天** 的对象才进入物理清理；删除前在并发安全的协议下再次核验引用，新引用与删除竞争时必须阻止引用已删对象。清理先支持 dry-run，再分批启用；未完成上传使用独立过期会话清理，不混入用户历史。第一版可先不启用物理 GC，宁可占空间也不误删附件。数据库恢复窗口必须有匹配的原件备份，不能只恢复元数据。

## 账号、解耦与部署

独立部署 `apps/sync-server` Go 服务，采用 Cobra + PostgreSQL / pgx；GORM 不是同步前置条件。2026-11-15 用户授权移除仓库旧家庭服务与 iOS / Swift macOS 客户端，不继承旧 household 数据模型，不操作旧线上数据。采用显式版本迁移，不用启动时自动改表代替迁移。Redis、WebSocket、多实例和云 OSS 先不引入。

个人账号 / 设备会话与现有 household 授权解耦；复用身份能力前必须审计现有 session 的 household 绑定。个人空间默认仅本人可见，不能自动给家庭成员权限，也不能靠客户端提供的空间 ID 授权。云同步账号独立于 ChatGPT provider；默认关闭，token 过期只暂停同步。退出账号不删除本地内容，关闭同步不等于删除云端内容。

v1 服务可读内容，不宣称端到端加密；远端访问必须 HTTPS，纯 loopback 开发可 HTTP。身份与会话第一版支持可撤销设备会话、基本登录限流；开发先用受控测试账号，不在同步工程里扩展公开注册、家庭邀请和完整商业账号系统。

产品展示保持低影响：本机保存与同步状态分别建模，平时不弹窗；设置页可查看积压、失败和冲突。开发与正式 App 的账号、目录、云端测试空间隔离。

## 验收底线

- 未登录、关闭同步、服务故障都不影响原有本地保存 / 重开 / MCP 编辑。
- 安静期、连续编辑上限、节流、重复保存、退避与唤醒使用可控时钟验证。
- 两设备修改不同 block 自动汇合；同块竞争、重排竞争、删除对编辑保留内容。
- 请求成功但确认丢失、确认期间继续输入、强退、重放及旧游标重建不漏不重。
- 引用附件缺失不假装同步完成；历史恢复能下载原件，GC 不删存活对象。
- 50 条 / 30 天取并集、归档时间边界、90 天游标过期和 tombstone 生命周期分别测试。
- 两个隔离账号不能跨空间访问正文、历史、对象或上传会话；未来版本不会被旧端保存抹掉。
