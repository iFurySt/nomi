# 个人文稿可选云同步 v1

## 目标

让两台 Mac 可选择登录并同步个人 `.nomi` 文稿，保持离线使用，按 block 增量传输；竞争修改保留双方。正文 / DSL / 画布存 PostgreSQL，附件先用服务器持久 disk 实现 ObjectStore。状态：正在实施；阶段完成后分别提交。

## 范围

- 包含：最小个人身份与设备会话、私有云资料库、版本化块与结构、磁盘对象存储、桌面调度 / outbox、冲突与有界历史、隔离双端验证。
- 不包含：CRDT / 实时协作、共享家庭 / group、手机 UI、Redis、云 OSS 接入、服务端 ZIP 加速、公开注册运营体系、无期限全量历史。
- [设计契约](../../design-docs/cloud-sync.md) 是调度数值、保留策略与同步语义的正式来源；计划不复制配置常量。

## 背景

- 相关文档：[架构](../../ARCHITECTURE.md)、[文件包](../../design-docs/nomi-package-format.md)、[安全](../../SECURITY.md)、[部署](../../DEPLOYMENT.md)。
- 代码边界：`packages/core` 领域 / 协议；`packages/host` 文稿保存、队列与网络适配；`packages/platform` 声明能力；`packages/ui` 可选同步入口；`apps/sync-server` 独立 Go 服务与存储。
- 已有 `StorageProvider`、Cobra、pgx 和家庭身份，但没有个人同步。Markdown / canvas 写入粒度仍为现有 block，不先改成字符级操作。
- 不更换本地 `.nomi` 主存储，不引入本机 Go 常驻服务，不操作正式 App 或真实家庭资料验证。

## 里程碑与交付门槛

### M1：协议与无附件同步内核

交付：版本化协议 fixtures、PostgreSQL 显式迁移、私有空间与测试身份、block / 结构版本检查、批次原子提交、幂等收据、增量游标、固定水位 bootstrap、tombstone。新建个人身份，不继承旧 household 模型；开发账号由运维命令创建，不做公开注册 UI。

验证：真实 PostgreSQL 下用两个模拟设备读写；不同 block 修改成功，同块冲突返回可恢复版本；重复请求、乱序事务提交、分页期间新增变化、跨账号读取和并发移动成环均有覆盖。

完成标准：不用桌面 UI 就能跑通“创建 → 拉取 → 两端编辑 → 冲突 / 删除 → 重连”。协议仍可调整，先用 synthetic 数据，不接生产资料库。

### M2：磁盘附件与文稿往返

交付：个人 ObjectStore 命名空间、鉴权上传 / 下载、摘要 / 大小校验、ready 发布、不可变原件与引用验证；文稿内容按块批量读写，完整 `.nomi` fixture 往返。

验证：Markdown、LaTeX、交互 DSL、内嵌画布、共享块、层级和图片 / PDF；上传中断、重复上传、原件缺失、路径逃逸、服务重启及持久卷重开。客户端提前上传依赖原件，失败不发布断链云端批次。

完成标准：新目录可从云端基线重建可打开文稿，语义与原件摘要一致。不做服务端 ZIP 和物理 GC。

### M3：桌面可选登录与日常同步

交付：默认关闭的设置入口、最小登录 / 退出和设备会话撤销、本地与云库显式绑定、host 持久队列 / 基线、保存恢复对账、调度 / 重试 / 拉取、远端事务应用、低影响状态显示。同块冲突至少有不丢数据的查看与选择入口后才开放测试。

验证：fake clock 调度矩阵；开启 / 关闭 / 过期 / 换账号；正常编辑、MCP 与外部文件变更；在途时继续输入、退出强退、断网重连、远端变化与 Undo、原有本地使用回归。

完成标准：两个隔离开发客户端稳定互通；关闭同步与未登录时仍完全可用。构建并重启 Nomi(Dev) 验收，不操作正式版。

### M4：有界历史、冲突完善与恢复

交付：最近条数与天数并集的按实体历史、选择旧版作为新提交、冲突双方及原件保护、日志过期后 bootstrap 对账、每日清理 dry-run、对象 GC 引用审计。历史记录从 M1 开始写入，本阶段落实保留 / 清理和用户恢复。

验证：长期未改仍有 50 条、短期高频保留 30 天、当前版不占额度；删除与修改、云端再次变化后的冲突选择、旧设备回来不复活；历史与附件引用、备份与恢复配对。

完成标准：故障矩阵通过且可恢复。物理对象 GC 只有在引用保护与并发测试通过后启用；可先保持关闭，不阻塞小范围试用。

### M5：受控试用与后续扩展入口

交付：独立开发 / 测试部署、迁移回退说明、数据备份与恢复演练、最小运行指标（积压、延迟、错误、冲突、对象容量，不记录正文）、本机两个独立进程、userData、资料目录、设备 ID 和会话的 synthetic 文稿测试。

完成标准：用户确认暂无双 Mac，以本机隔离双客户端完成本阶段；不将模拟称作双物理设备；前面阶段通过后才建议用户把资料库接入试用。正式部署 / 发布另按发布流程执行，不因本计划创建自动部署。

后续候选：替换云 OSS provider、iPhone 同步适配、按需附件与离线保留、服务端打包下载、共享空间；均不扩大 v1 验收范围。

## 风险与缓解

- 本地保存与 outbox 存在双写窗口：保存恢复标记 / 基线对账，不靠内存事件保证可靠性。
- 自增游标乱序提交导致漏拉：设计要求提交有序水位，用真实并发事务测试。
- 旧确认覆盖新输入：冻结在途批次并按本地代确认，保留后续编辑。
- 家庭授权误复用：个人空间独立，所有查询与对象访问显式检查账号归属。
- 画布块较大、历史增长：沿用内容预算，批量提交，保留策略先监控；不提前迁移冷数据。
- FS 误认为云 OSS：明确单机风险，持久卷和数据库 / 原件配对恢复；现有家庭 FS 删除逻辑不得直接复用。

## 验证与回退

- 文档阶段：`make check-docs`、`git diff --check`。
- 开发阶段：各切片专项 Go / PostgreSQL / TypeScript 测试；客户端变更运行 `pnpm check`、相关 host / core 测试、`pnpm build` 与隔离桌面回归。具体命令随落地补入，未运行不标通过。
- 协议使用同源 fixtures，未来 Swift 可复用，不要求 iPhone 先运行 JS。
- 默认关闭 feature；停用后本地保存继续，保留同步元数据供诊断 / 恢复，不把关闭当作清空云端。
- 首次开启前保留本地备份；新服务使用独立数据库，不迁入或清理旧家庭生产数据；生产变更另需正式备份和恢复检查。
