# 交互块多端架构与体验设计

## 目标与范围

解释当前交互生成质量限制，提出可审查的 DSL / 多端 renderer / Web 扩展方案与验收标准。用户选择先完成架构和体验设计，确认后再实现。此次不修改运行代码，不安装依赖，不操作正式或开发 App，不发布版本。

## 背景与约束

- 当前能力见 `packages/core/src/interactive/types.ts`、host 生成提示与 `docs/design-docs/canvas-ai-generation.md`。
- 同一 DSL 要支持 Electron 与未来原生移动端的不同呈现。
- 已有 `.nomi` 身份、个人进度、取消 / 冲突保护不能因扩展丢失。
- 保留工作区独立的桌面窗口输入策略改动。

## 风险与处理

- 任意 HTML 不能自动原生化：区分 portable、可选 Web 视图和 Web-only 能力。
- iframe 不提供可靠计算资源隔离：生产启用前先验证独立停止与正文可用性。
- 研究结论被误认为已实现：所有新能力明确标记提案，现状文档只补充链接。
