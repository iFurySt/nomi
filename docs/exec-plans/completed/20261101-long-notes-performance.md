# 超长混排文稿性能测试与优化

## 目标与约束

建立可重复的 Electron 压测，定位长文与混排的主线程热点，并在保留 Markdown / LaTeX、IME、撤销、目录与保存语义的前提下降低交互延迟。只使用隔离 profile 和合成文稿；不得改写用户 Transformer 或教程。保留已有未提交工作。

## 范围

- 长篇单一 Markdown、多个文本块与图片 / 文件 / 交互混排。
- 打开、输入到下一帧、滚动、切换、保存 / 重开；记录规模、环境与限制。
- 根据实测选择增量计算、结构共享、按需呈现等优化；不为宣传强行承诺 VS Code 的所有大文件能力。

## 风险

编辑器虚拟化可能破坏原生选区、输入法、查找和拖动。优先修复实测热路径；任何延后工作必须保留关闭前 flush 和撤销正确性。绝不以丢弃内容或关闭功能换速度。

## 里程碑

- [x] 建立合成样本与基线，保存 CPU / latency 报告。
- [x] 实现有证据支持的优化，比较同样输入。
- [x] 验证正文完整性、保存重开、IME / 混排回归。
- [x] 文档、history、正式 App 构建重启与隔离压测窗口验收。

## 验证

生产模式真实 Electron；分开报告本地 renderer 与文件保存成本。性能数字为当前机器样本，不当作跨平台 SLA。与基线使用相同文稿、窗口和输入序列；报告 p50 / p95、长任务、DOM / heap 等。

## 结果

输入热路径优化与完整 Notes / IME 回归完成。性能契约和基线报告见 `docs/design-docs/notes-performance.md`。首次打开约 1 秒、首次建包约 6 秒记录为后续瓶颈，未扩大 DSL 容量。回归捕获首次指针返回的块定位问题并修复。

423 单测、类型、生产构建、Notes / IME / Canvas 回归和基础 CI 全部通过。正式 Nomi 已确认保存后正常退出并启动最新构建，文稿页恢复原先选中项；未编辑用户正文。
