# 笔记与无限画布整体设计

## 目标

明确 Nomi 下一阶段的笔记与无限画布架构：完整长笔记支持 Markdown / LaTeX，混排图片、文件和手写；macOS 编辑后可在 iPad / iPhone 渲染并继续编辑；DSL 是 AI 可读、可写的文档契约。

用户已确认第一版以“完整笔记放在无限画布里”为主，兼容独立图片、附件和手写对象。

## 范围

本轮交付设计、DSL 示例、分阶段实施顺序与验证门槛，不安装新依赖、不实现编辑器、不裁剪现有金融功能，也不改生产协议或数据。

## 步骤

- [x] 阅读仓库约定、当前桌面 / iOS / server 边界。
- [x] 查询一手资料：JSON Canvas、Excalidraw、BlockSuite、tldraw、Yjs、Apple PencilKit、Pointer Events、CodeMirror、KaTeX 与声明式语法。
- [x] 确认长笔记优先的交互取向。
- [x] 编写整体设计、DSL 草案与可检查的示例。
- [x] 明确快照与协作历史、文件编辑入口、笔迹可移植性、移动端输入风险。
- [x] 同步产品 / 架构导航，校验文档与示例，记录并归档本轮设计。

## 关键约束

- 不把画布库私有格式作为 Nomi 公共文档契约。
- 不把 Markdown / LaTeX 编辑结果变成不可逆截图，不把笔迹只保存为图片。
- DSL 语义状态和 CRDT 并发历史职责不同；必须明确导入、外部文件编辑和恢复行为，不能存在两个可以互相覆盖的独立主状态。
- 现有家庭全共享权限不能自动用于个人笔记。
- 技术候选是设计建议，需通过原型门槛后才能锁定依赖与实现方案。
