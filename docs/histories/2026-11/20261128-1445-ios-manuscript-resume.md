# 切回 iOS 文稿时恢复正文

用户从其他应用返回 Nomi 时偶尔只看到操作按钮，切换文稿才恢复正文。在 Duo 模拟器中打开带表格、清单和公式的文稿，切到系统设置，在后台终止该文稿的 WebKit 内容进程，再返回仍在运行的 Nomi，旧实现可稳定出现同样的空白。

Swift 端缓存了上一次排版的标题和正文。WebKit 进程被回收时页面随之消失，但缓存仍表示文稿已经显示。现在由 `ManuscriptPreview` 在进程终止时让缓存失效，回到前台后使用当前标题、正文草稿和版面重新加载本地阅读器，并恢复滚动位置。正常切回只检查页面是否存在，保留原有编辑视图。延迟回调只作用于发起它的页面。

在同一台 Duo 模拟器上，对折叠外屏的竖向、左右横向，以及展开内屏的竖向、倒置、左右横向，分别重复后台终止排版进程的操作。七次均保持同一个 Nomi 应用进程和同一篇文稿，返回后抽查的正文区域与切出前逐像素一致。

新增 WebKit 回归测试，覆盖普通切回保留原页面、进程终止后按最新草稿重建并恢复阅读位置，以及缺少终止通知时的空页面恢复。五项渲染测试和公式编辑、保存后重开的界面测试通过。开发构建已安装到配对 Duo。

额外运行的编辑界面测试在新建文稿后找不到清单工具按钮。用改动前的实现运行相同测试也停在这一步，此时尚未创建 Markdown 阅读器。
